### AB-DIAG-01. سياق النظام

![سياق النظام](svg/01-system-context.svg)

- **الهدف والنطاق:** من يتعامل مع AgentBridge ومن أي حد؛ النطاق هو نشر التقييم المحلي.
- **حدود الثقة:** المتصفح ↔ API (مفتاح مستأجر ووكيل نفس الأصل)؛ الصندوق ↔ المضيف؛ الخادم المولّد ↔ upstream.
- **المدخلات والمخرجات:** مواصفة OpenAPI + مفتاح مستأجر → شهادة وشارة وأدلة وحزمة خادم.
- **مسارات البيانات الحساسة:** محتوى المواصفة (قد يحوي PII) يبقى داخل خط المعالجة؛ اعتماديات upstream مظاريف مشفرة فقط؛ مفاتيح المستأجرين مجزأة.
- **حالات الفشل المغلقة:** مفتاح مستأجر غير صالح → 401 موحد؛ محاولة خروج شبكي من الصندوق → `HARD_LIVE_PROBES_FAILED`.
- **مراجع المصدر:** `apps/dashboard/` و`apps/api/src/routes/pipelines.route.ts` و`packages/orchestrator/src/engine.ts` و`infra/hardening/sandbox.ts` و`docs/security.md` §8.1.

### AB-DIAG-02. مساحات العمل واتجاهات التبعية

![مساحات العمل](svg/02-workspaces.svg)

- **الهدف والنطاق:** بنية pnpm workspaces وقاعدة التبعية الحديدية (المصدر نحو العقود الداخلية؛ النطاق لا يستورد البنية التحتية).
- **حدود الثقة:** حدود الحزم — `apps/` تجميع، و`packages/` تنفيذ، و`shared` تعريف.
- **المدخلات والمخرجات:** لا شيء (عرض بنيوي).
- **مسارات البيانات الحساسة:** لا شيء.
- **حالات الفشل المغلقة:** أي خرق طبقات يفشل في lint/typecheck (`eslint.config.mjs` و`tsc --noEmit` لكل حزمة).
- **مراجع المصدر:** `pnpm-workspace.yaml` و`docs/systems.md` (جدول الملكية) و`package.json` لكل حزمة.

### AB-DIAG-03. مسار OpenAPI حتى الشهادة

![خط المعالجة](svg/03-openapi-pipeline.svg)

- **الهدف والنطاق:** DAG الحتمي بمراحله الثماني مع حلقة الإصلاح المحدودة وبوابة HITL.
- **حدود الثقة:** محتوى المواصفة بيانات غير موثوقة (مسح حقن)؛ مخرجات الوكلاء غير موثوقة حتى تمر بتحقق Zod.
- **المدخلات والمخرجات:** مواصفة → مواصفة مطبّعة → مواصفة محللة → تصاميم أدوات → خادم مولّد → تقرير أمني → شهادة.
- **مسارات البيانات الحساسة:** حقول PII تُكشف وتُقيّم أثناء التحليل؛ والحِمل يُحوَّر قبل التخزين التدقيقي.
- **حالات الفشل المغلقة:** نتيجة حرجة → رفض فوري؛ استنفاد دورات الإصلاح → `needs_human`؛ إحالات غير صالحة → إصلاح؛ خرج LLM مخالف للمخطط → فشل منظّم.
- **مراجع المصدر:** `packages/orchestrator/src/graph.ts` و`engine.ts` و`retry-policy.ts` و`packages/spec-parser/src/` و`packages/analyzer/src/` و`packages/generator/src/` و`packages/hardening/src/` و`packages/evaluator/src/citation-verifier.ts` و`docs/orchestration.md`.

### AB-DIAG-04. مسار طلب MCP

![مسار طلب MCP](svg/04-mcp-request-path.svg)

- **الهدف والنطاق:** طلب واحد من وكيل ذكاء اصطناعي عبر الخادم المولّد إلى upstream.
- **حدود الثقة:** مدخل الوكيل يتحقق بمخطط zod لكل أداة؛ واستجابات upstream تُنظف قبل الإرجاع.
- **المدخلات والمخرجات:** نداء أداة JSON-RPC → نتيجة أداة أو خطأ منظّم.
- **مسارات البيانات الحساسة:** اعتماديات upstream من البيئة حصراً (`UPSTREAM_API_KEY` اختياري)؛ ودقائق فشل upstream لا تُسرَّب للوكيل أبداً (HD-02).
- **حالات الفشل المغلقة:** وسائط غير صالحة تُرفض؛ نطاقات ناقصة تُرفض؛ غياب `UPSTREAM_BASE_URL` يفشل عند الإقلاع؛ المهلة وتنقية الأخطاء مفروضتان.
- **مراجع المصدر:** `packages/generator/src/templates/` (server وtools وupstream-client وconfig) و`packages/hardening/src/live-probes.ts`.

### AB-DIAG-05. الوكلاء وDAG والإصلاح وHITL واللقطات الموقعة

![الوكلاء وDAG](svg/05-agents-dag.svg)

- **الهدف والنطاق:** كيف تختلط العقد الحتمية بوكلاء النموذج، وكيف يُحدّ الإصلاح، وكيف يبقى الإيقاف/الاستئناف موثوقاً.
- **حدود الثقة:** الوكلاء يقترحون والحتمي ينفذ؛ اللقطات موقعة SHA-256 وتُتحقق حقلاً-بحقل عند الاستئناف.
- **المدخلات والمخرجات:** سياق خط المعالجة → نتائج العقد (`completed | failed(retryable) | failed(fatal) | needs_repair`).
- **مسارات البيانات الحساسة:** مطالب الوكلاء تستقبل كتل مواصفة محوَّرة ومحددة؛ وكل نداء أداة يُدقَّق.
- **حالات الفشل المغلقة:** سقف الإصلاح (3) → `needs_human`؛ النتيجة الحرجة → فشل فوري؛ عدم مطابقة بصمة اللقطة → رفض الاستئناف.
- **مراجع المصدر:** `packages/orchestrator/src/engine.ts` و`context-store.ts` و`event-log.ts` و`packages/agents/src/` و`docs/agents.md` و`docs/orchestration.md`.

### AB-DIAG-06. طبقات الذاكرة L0–L4

![طبقات الذاكرة](svg/06-memory-layers.svg)

- **الهدف والنطاق:** ذاكرة العمل والعرضية والدلالية والمتجهية ودولاب التعلم — كلها خلف منافذ بمحولات قابلة للتبديل.
- **حدود الثقة:** كل نداء مخزن يستقبل `tenantId` (عزل بنيوي)؛ وPII يُحوَّر قبل L1/L3؛ وL3 تخزن تضمينات فقط لا نصاً خاماً حساساً.
- **المدخلات والمخرجات:** أحداث التشغيل → L1؛ والكيانات الدائمة → L2؛ ونص الدرس → تضمين حتمي → فهرسة L3.
- **مسارات البيانات الحساسة:** L2 مصدر الحقيقة الوحيد؛ والتشغيل الكامل قابل لإعادة البناء من L2 + L1 المؤرشفة (اختبارات phoenix).
- **حالات الفشل المغلقة:** استعلام بلا نطاق مستأجر مستحيل بالبناء؛ وحالة ما بين التشغيلات تعبر عبر لقطات موقعة فقط.
- **مراجع المصدر:** `packages/memory/src/` (episodic-store وsemantic-store وvector-store وflywheel) و`packages/infra/src/pgvector-store.ts` ومخازن `prisma-*` و`docs/memory.md`.

### AB-DIAG-07. OIDC/OAuth/PKCE وهوية مساحة العمل

![مصادقة OIDC](svg/07-oidc-auth.svg)

- **الهدف والنطاق:** إعداد SSO للمؤسسات ومسار callback مع تحقق محلي للتوكن.
- **حدود الثقة:** المُصدر وJWKS يجب أن يكونا HTTPS (zod + HB-12)؛ وجلب JWKS بقائمة سماح وIP مثبت وبلا redirects؛ وتوكنات IdP لا تُخزن إطلاقاً.
- **المدخلات والمخرجات:** `id_token` → ادعاءات متحققة → Bearer داخلي قصير العمر → جلسة معتمة خادمية.
- **مسارات البيانات الحساسة:** معرفات الجلسات تُخزن مجزأة (SHA-256)؛ و`clientSecret` عبر البيئة حصراً؛ و`jwksUrl` لا يُكشف عبر الـAPI.
- **حالات الفشل المغلقة:** مُصدر خاطئ → 401 قبل أي منطق مستأجر (HD-08)؛ JWKS غير مشفر محجوب؛ التوكنات المنتهية/الضخمة مرفوضة.
- **مراجع المصدر:** `packages/infra/src/oidc-verifier.ts` و`packages/infra/src/sso-store.ts` و`apps/api/src/plugins/sso.plugin.ts` و`apps/api/src/routes/oidc.route.ts` و`docs/security.md` §8.1.

### AB-DIAG-08. عزل البيانات (RLS وRedis وpgvector)

![عزل البيانات](svg/08-data-isolation.svg)

- **الهدف والنطاق:** عزل المستأجرين عبر PostgreSQL (RLS) وRedis (بادئة المفاتيح) وpgvector (مفتاح مركب).
- **حدود الثقة:** التطبيق يتصل بدور مقيد (`NOSUPERUSER` و`NOBYPASSRLS`)؛ وفحص الإقلاع يرفض fail-closed أي دور خارق أو ملكية جداول.
- **المدخلات والمخرجات:** استعلامات بنطاق مستأجر حصراً؛ و`SET LOCAL app.tenant_id` داخل كل معاملة.
- **مسارات البيانات الحساسة:** صفوف المتجهات بمفتاح `(tenant_id, run_id, id)`؛ ومفاتيح Redis بنمط `tenant:run:*` وعمر 7 أيام.
- **حالات الفشل المغلقة:** قراءة عابرة للمستأجرين → فارغة/مرفوضة بـRLS؛ اتصال superuser أو BYPASSRLS → رفض إقلاع.
- **مراجع المصدر:** `packages/infra/src/prisma-scope.ts` و`prisma-scope-hardening.ts` و`prisma-scope-role.ts` و`prisma-scope-tables.ts` و`docs/security.md` §8.

### AB-DIAG-09. إصدار الشهادة وتوقيعها وإبطالها

![الشهادة](svg/09-certification.svg)

- **الهدف والنطاق:** كيف تصبح التشغيلة شهادة موقعة قابلة للتحقق علناً، وكيف تتطور الثقة (دوران وإبطال).
- **حدود الثقة:** بوابة الدرجة (≥ 85 وصفر حرج)؛ توقيعات Ed25519؛ ومسار التحقق العام يكشف قائمة بيضاء صارمة فقط.
- **المدخلات والمخرجات:** بصمة المخرجات + التقرير الأمني → شهادة + معرّف `AB-<16hex>` + شارة.
- **مسارات البيانات الحساسة:** مسار التحقق يعيد `{verificationId, finalScore, granted, issuedAt, artifactsHash}` فقط — بلا أي بيانات مستأجر.
- **حالات الفشل المغلقة:** نتيجة حرجة → رفض تلقائي مهما كانت الدرجة؛ keyId ملغى → يرفض التحقق؛ توكيغات المفتاح القديم تبقى قابلة للتحقق خلال نافذة الدوران.
- **مراجع المصدر:** `packages/evaluator/src/certificate.ts` و`certificate-signing.ts` و`badge.ts` و`apps/api/src/routes/certificate-revoke.route.ts` و`docs/security.md` §8.1. وKMS الخارجي: `PLANNED` و`NOT_VERIFIED`.

### AB-DIAG-10. سلسلة التدقيق وكشف التلاعب

![سلسلة التدقيق](svg/10-audit-chain.svg)

- **الهدف والنطاق:** سجل تدقيق إلحاق-only بسلسلة هاش لكل مستأجر؛ أي عبث يُكشف في موضع دقيق.
- **حدود الثقة:** `hash_n = SHA-256(hash_{n-1} + event_n)` بالارتكاز على GENESIS؛ وطوابير كتابة لكل مستأجر تمنع السباقات.
- **المدخلات والمخرجات:** أحداث خط المعالجة وقرارات البوابات → سجلات مترابطة؛ و`verifyChain(tenantId)` يعيد البناء والتحقق.
- **مسارات البيانات الحساسة:** الحِمل يُختزل ويُحوَّر قبل التخزين.
- **حالات الفشل المغلقة:** أي تعديل تاريخي يكسر السلسلة ويُبلّغ عن الموضع الدقيق.
- **مراجع المصدر:** `packages/infra/src/audit-chain.ts` و`docs/memory.md` (قسم سجل التدقيق).

### AB-DIAG-11. حدود الصندوق المعزول

![الصندوق المعزول](svg/11-sandbox.svg)

- **الهدف والنطاق:** الحاوية المقيدة التي تنفذ الفحوص الحية على الخادم المولّد.
- **حدود الثقة:** جذر نظام ملفات للقراءة فقط، ومستخدم غير جذر `65532`، وسقوف CPU/ذاكرة/عمليات، وseccomp افتراضي، وno-new-privileges، وشبكة محصورة برمجياً على localhost (`assertLocalhostOnly`).
- **المدخلات والمخرجات:** الخادم المولّد + خطة الفحوص → نتائج حية أو `HARD_LIVE_PROBES_FAILED`.
- **مسارات البيانات الحساسة:** الفحوص تضرب النماذج المحلية فقط؛ ولا شبكة خارجية من داخل الحاوية.
- **حالات الفشل المغلقة:** التنفيذ كجذر والكتابة على نظام الملفات ومحاولة الشبكة الخارجية كلها تفشل (`sandbox.spec.ts` يثبتها).
- **مراجع المصدر:** `infra/hardening/sandbox.ts` و`docker/sandbox.Dockerfile` و`docker-compose.sandbox.yaml` و`packages/hardening/src/live-probes.ts` و`mock-upstream.ts` و`mock-oidc-provider.ts`. وسياسة الخروج العامة: `PLANNED`.

### AB-DIAG-12. النسخ الاحتياطي والاحتفاظ والحذف

![النسخ والاحتفاظ](svg/12-backup-retention.svg)

- **الهدف والنطاق:** دورة حياة البيانات كاملة: احتفاظ لكل صنف، ونسخ/استعادة مُتحقق، وحذف مزدوج.
- **حدود الثقة:** سياسة الاحتفاظ fail-closed في الإنتاج (الإعداد الخاطئ يرفض الإقلاع)؛ و`auditLog` و`revocations` دائمان بالسياسة.
- **المدخلات والمخرجات:** `RETENTION_POLICY_JSON` → مسوحات مجدولة؛ وحذف مساحة العمل → إزالة صف L2 ومتجه L3 ذرياً.
- **مسارات البيانات الحساسة:** النسخ تحوي بيانات تشغيل — الاستعادة مُتحقق، وانتهاء صلاحيتها بالسياسة نفسها.
- **حالات الفشل المغلقة:** حذف درس flywheel يزيل صف L2 وفهرس L3 معاً؛ وسجلات التدقيق تنجو من الحذف بالسياسة.
- **مراجع المصدر:** `.env.example` (`RETENTION_POLICY_JSON`) و`apps/cli/src/ops/` و`packages/memory/src/deletion-operations.ts` و`packages/infra/src/audit-chain.ts`. ونسخ KMS الخارجية: `PLANNED` و`NOT_VERIFIED`.

### AB-DIAG-13. مخازن البيانات: Redis وpgvector

![مخازن البيانات](svg/13-data-stores.svg)

- **الهدف والنطاق:** أين تسكن الذاكرة التشغيلية والدائمة — Redis لحالة التشغيل العرضية والحراسة التشغيلية، وPostgreSQL+pgvector للكيانات الدائمة والتضمينات — وكيف تتبادل المنافذُ نفسها بين محولات داخل الذاكرة والمحولات الحية.
- **حدود الثقة:** كل نداء منفذٍ محصور بمستأجره بنيوياً؛ مفاتيح Redis تحمل معرّفَي المستأجر والتشغيل بعمر 7 أيام يُجدَّد مع كل كتابة؛ وصفوف المتجهات لا تخزن نصاً خاماً حساساً (تضمينات فقط).
- **المدخلات والمخرجات:** أحداث التشغيل ونقاط الاستئناف → تدفقات وأقساس حالة في Redis؛ عدادات حد المعدل وحصة SSE ودفتر الميزانية → مفاتيح Redis؛ الكيانات الدائمة → جداول L2؛ تضمينات الدروس (1536 بعداً) → فهرس L3 في pgvector؛ ودروس دولاب التعلم تُكتب مزدوجاً في صف L2 وفهرس L3 بحذف ذري.
- **مسارات البيانات الحساسة:** يُحوَّر PII قبل التخزين العرضي والمتجهي؛ وL2 مصدر الحقيقة الوحيد الذي يُعاد بناء التشغيل منه (L1 قابل للمحو، وL3 قابل لإعادة الفهرسة).
- **حالات الفشل المغلقة:** وضع التطوير لا يحتاج خدمات خارجية (محولات داخل الذاكرة)؛ ووضع live يرفض الإقلاع غياب `DATABASE_URL`/`REDIS_URL`؛ وحذف الدرس يزيل صفَّه في L2 وفهرسَه في L3 معاً.
- **مراجع المصدر:** `packages/memory/src/` (episodic-store وsemantic-store وvector-store وflywheel) و`packages/infra/src/pgvector-store.ts` و`rate-limit-redis.ts` و`sse-quota-redis.ts` و`budget-redis-ledger.ts` و`run-lock.ts` و`packages/llm/src/embeddings-provider.ts` و`docs/memory.md`.

### AB-DIAG-14. الموقع الثابت مقابل المنصة الكاملة

![الموقع الثابت مقابل المنصة](svg/14-website-vs-platform.svg)

- **الهدف والنطاق:** ما هو الموقع الثابت تحت `website/` وما ليس هو، مقارنةً بالمنصة الكاملة ذاتية الاستضافة.
- **حدود الثقة:** الموقع الثابت محتوى جاهز للقراءة فقط (بلا زمن تشغيل خادمي ولا أسرار ولا نماذج إدخال ولا بيانات مستأجرين)؛ وحدود المنصة تحوي خدمات حية خلف مصادقة وعزل.
- **المدخلات والمخرجات:** متصفح الزائر ← صفحات ثابتة (HTML/CSS/SVG) · مستخدم المنصة ← لوحة موثقة ← API ← مسار المعالجة ← شهادة.
- **مسارات البيانات الحساسة:** لا شيء في الموقع الثابت؛ وفي جانب المنصة تبقى مفاتيح المستأجرين مجزأة وبياناتهم خلف أسطح موثقة محصورة بنطاق المستأجر.
- **ما لا ينفذه الموقع إطلاقًا:** واجهة Fastify، وPostgreSQL/Redis/pgvector، وصندوق Docker، وتسجيل دخول حقيقي، وSSE خلفي، وتوليد وفحص MCP الكامل، أو أي تخزين أسرار أو بيانات مستخدمين.
- **حالات الفشل المغلقة:** الموقع لا يستطيع تنفيذ شيفرة ولا استقبال إرساليات (بلا نماذج ولا تتبع ولا زمن تشغيل خادمي)؛ والمنصة ترفض الوصول غير الموثق إلى أسطح المستأجرين.
- **مراجع المصدر:** `website/` (الصفحات الثابتة) و`apps/api/src/routes/` و`docker-compose.sandbox.yaml` و`docs/security.md` §8.1.
